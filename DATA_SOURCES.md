# Data Sources and Release Policy

This anonymous review artifact distinguishes between **public third-party inputs** and **study-generated evidence**.

## Public third-party inputs

Public datasets, benchmark repositories, and external artifacts should be referenced by source URL and pinned revision rather than copied into this repository whenever practical.

The study's external-compatibility analysis considers public systems/benchmarks such as:

- NetAgentBench
- Cornetto
- NetConfArena

Their public artifacts should be obtained from their original repositories or archival locations. Where a reproducibility script depends on one of these sources, the release should record a commit/tag/archive identifier and checksum when available.

No public third-party dataset should be mirrored here solely for convenience if an authoritative source remains available.

## Study-generated evidence

The following categories are eligible for inclusion because they were generated by the study and are needed to audit or reproduce reported results:

- normalized AI-generated transaction proposals;
- frozen task/model/context assignments;
- deterministic semantic-evidence records;
- deterministic reference labels and obligation vectors;
- B1--B5 and Full guard scores;
- PE11 analysis inputs;
- PE13 recovery-analysis inputs;
- D6 historical live-evidence summaries;
- PE12 prospective live-evidence summaries;
- D7 compatibility-audit rows;
- hashes/checksums needed to verify evidence provenance.

These files should be released only after sanitization.

## Sanitization rules

Remove or replace:

- author names and affiliations;
- email addresses and institutional identifiers;
- API keys, authorization headers, tokens, cookies, and secrets;
- provider account identifiers and billing metadata;
- private endpoint URLs;
- local filesystem paths;
- hostnames, usernames, or machine-specific metadata that can identify the authors;
- manuscript text or figure assets.

Do **not** alter scientific fields such as task IDs, proposal contents, deterministic labels, obligation results, frozen assignments, seeds, or analysis values unless the transformation is documented and provably semantics-preserving.

## Raw model-provider records

Raw model responses can carry unnecessary provider metadata. For anonymous review, prefer a normalized record containing only fields needed to reproduce the transaction and its provenance, for example:

```json
{
  "case_id": "...",
  "model_alias": "...",
  "context_condition": "...",
  "prompt_hash": "...",
  "response_text": "...",
  "parsed_transaction": {},
  "parse_status": "..."
}
```

Do not publish request headers, access tokens, account IDs, invoice/billing fields, or private service URLs.

## Integrity

Generated evidence should be accompanied by SHA-256 checksums where practical. Any sanitization step should preserve a mapping from the released artifact to the frozen scientific record without exposing identifying metadata.
